# mo-info-bar

**One-shot installer/refresher for the bottom-bar info-bar status line.** Generates a version-stable wrapper at `~/.claude/mo-info-bar.sh` that resolves the latest installed plugin version dynamically, then writes `statusLine` into `~/.claude/settings.json` pointing at the wrapper.

Why a wrapper instead of a direct path: Claude Code's `statusLine.command` does NOT expand `$CLAUDE_PLUGIN_ROOT` in this context (verified by user reports — the literal string ends up trying to invoke `/scripts/info-bar.sh`). Hardcoding the absolute version-numbered path works but breaks on every plugin upgrade. The wrapper is a stable indirection: settings.json points at `~/.claude/mo-info-bar.sh` once, and the wrapper picks up new plugin versions automatically.

## When invoked

- **First-time setup (`/mo-init` Step 5.5):** delegated to this command after the user opts in.
- **Plugin upgrade housekeeping:** the wrapper auto-discovers new versions, but if the plugin cache structure changes or the wrapper itself was deleted, re-run this command to regenerate it.
- **After cache cleanup:** if you ran `rm -rf ~/.claude/plugins/cache/...` to force a clean re-install, re-run to regenerate the wrapper.
- **Anytime you want to verify the wiring:** idempotent; running it on a healthy setup just rewrites the same files.

## Preconditions

- `$CLAUDE_PLUGIN_ROOT` is set (it is, when this command runs — Claude Code sets it in command/hook contexts).
- `$CLAUDE_PLUGIN_ROOT/scripts/info-bar.sh` exists (the script this wraps).
- `~/.claude/settings.json` exists OR can be created.

## Execution

### Step 1 — Sanity-check the plugin script is present

```bash
script="$CLAUDE_PLUGIN_ROOT/scripts/info-bar.sh"
if [[ ! -f "$script" ]]; then
  echo "error: info-bar script not found at $script — plugin may be partially installed. Run /mo-doctor for a full check." >&2
  exit 1
fi
```

### Step 2 — Write the wrapper to `~/.claude/mo-info-bar.sh`

The wrapper resolves the latest installed plugin version at every invocation (using a small Python helper for semver-aware sort — Python is already a hard plugin dep per `scripts/doctor.sh`).

Write the following content to `$HOME/.claude/mo-info-bar.sh` via the `Write` tool:

```bash
#!/usr/bin/env bash
# mo-info-bar.sh — version-stable launcher for the millwright-overseer-development-machine
# info-bar status-line script.
#
# Generated by /mo-info-bar (or /mo-init Step 5.5). DO NOT hand-edit — re-run
# /mo-info-bar to refresh after a plugin upgrade or cache cleanup.

set -euo pipefail

plugin_dir="$HOME/.claude/plugins/cache/millwright-overseer/millwright-overseer-development-machine"

if [[ ! -d "$plugin_dir" ]]; then
  echo "mo · plugin not installed"
  exit 0
fi

latest="$(python3 - "$plugin_dir" <<'PYEOF' 2>/dev/null
import os, re, sys
root = sys.argv[1]
if not os.path.isdir(root):
    sys.exit(1)
def key(name):
    m = re.match(r'^[0-9]+(?:\.[0-9]+)*$', name)
    if not m:
        return (-1,)
    return tuple(int(x) for x in name.split('.'))
versions = [d for d in os.listdir(root) if os.path.isdir(os.path.join(root, d))]
versions.sort(key=key)
if not versions:
    sys.exit(1)
print(os.path.join(root, versions[-1]))
PYEOF
)"

if [[ -z "$latest" || ! -d "$latest" ]]; then
  echo "mo · plugin path resolution failed (no version dirs under $plugin_dir)"
  exit 0
fi

script="$latest/scripts/info-bar.sh"
if [[ ! -f "$script" ]]; then
  echo "mo · info-bar script missing at $script"
  exit 0
fi

exec bash "$script"
```

Then `chmod +x ~/.claude/mo-info-bar.sh` so Claude Code can invoke it directly.

### Step 3 — Smoke-test the wrapper

```bash
bash "$HOME/.claude/mo-info-bar.sh"
```

Expected output: `mo · no active cycle` (or `mo · cycle <slug> · ...` if you have an active workflow). If the wrapper errors or prints `mo · plugin path resolution failed`, do NOT proceed to Step 4 — investigate first.

### Step 4 — Update `~/.claude/settings.json` `statusLine` block

Use the `update-config` skill to set the `statusLine` field. The command must be the absolute path to the wrapper (NOT a `$VAR`-expanded form — see the rationale at the top of this file):

```json
{
  "statusLine": {
    "type": "command",
    "command": "<absolute path to $HOME/.claude/mo-info-bar.sh>"
  }
}
```

Resolve `$HOME` to its concrete value before writing. The skill should overwrite any existing `statusLine` block (including stale ones with `$CLAUDE_PLUGIN_ROOT` template strings — those are exactly what we're fixing).

If `update-config` is not available, fall back to a small Python edit that preserves all other fields:

```bash
python3 - <<PYEOF
import json, os
path = os.path.expanduser("~/.claude/settings.json")
data = {}
if os.path.isfile(path):
    with open(path) as f:
        data = json.load(f)
data["statusLine"] = {
    "type": "command",
    "command": os.path.expanduser("~/.claude/mo-info-bar.sh"),
}
with open(path, "w") as f:
    json.dump(data, f, indent=2)
    f.write("\n")
PYEOF
```

### Step 5 — Report + restart instruction

Print the canonical hand-off message:

> "Info-bar wired. ~/.claude/mo-info-bar.sh is the version-stable launcher; ~/.claude/settings.json now points at it. **Restart Claude Code for the bar to appear** — `statusLine` is loaded at session start, not hot-reloaded. After restart you should see `mo · no active cycle` at the bottom of the terminal (until you run `/mo-run`)."

If the user reports the bar still doesn't appear after a full restart:

1. Verify `bash ~/.claude/mo-info-bar.sh` prints something (Step 3).
2. Verify `~/.claude/settings.json` `statusLine.command` is the absolute path (`/Users/...` or equivalent), NOT `$CLAUDE_PLUGIN_ROOT/...`.
3. Check Claude Code's terminal supports the status line (some constrained terminals — small windows, certain SSH configurations, tmux/screen setups — may suppress it).

## Notes

- **Why no `$CLAUDE_PLUGIN_ROOT` expansion:** Claude Code expands env vars in command/hook invocations, but `statusLine.command` is invoked from a different context where `$CLAUDE_PLUGIN_ROOT` is not in scope. This was discovered after the v0.7.0 ship; the v0.7.2 fix is this command + a `/mo-init` Step 5.5 update that uses absolute paths.
- **The wrapper survives plugin upgrades** because it resolves the highest installed version at every invocation. Settings.json never needs to change again unless the wrapper itself moves.
- **The token-tracking hook runs independently** of this wiring. Even if the status bar isn't installed (or breaks), `quest/<slug>/.stage-tokens.json` and `quest/<slug>/usage.log` continue to receive per-stage data. The bar is a display only.
- **No restart-free path exists.** Modifying `settings.json` mid-session does not hot-reload `statusLine` — Claude Code reads it at session start. Both this command and `/mo-init` Step 5.5 print the restart instruction.
